# 三亮点演示与答辩

适用版本：2026-10-16 W14 本地交付。约 5 分钟，以“从需求到出行”串联。老师的三亮点是主线；多轮、多日、路书已有本地实现，未生产化的部分保留边界说明。

## 准备与备用流程

准备当前包、Node 22、现代浏览器。真实模式需个人 DeepSeek Key、服务端 MCP Token 和道路/图片网络；私下配置，不投屏 Key。只有 DEPLOY.md 的真实验证通过后才用线上网址演示新版。

先用“上海 · 梧桐街区”保存示例收藏和 HTML 路书备用，明确叫内置示例。离线库需首次联网准备。只导出提交版；不以模拟响应或历史测试截图冒充实时服务。

## 答辩口径

**与普通 AI 攻略区别？** 用版本化行程连接提案、来源、地图、时间、编辑和路书，减少用户自行查找与维护改动；不是给文字贴一张地图。

**模型编地点怎么办？** 提案可能错，但模型坐标/营业信息不直接落图。名称、城市、地址和唯一性不通过就提示、尝试备选或回退。精确匹配有别名识别不足的局限。

**是否最优？** 不是。AI 排序、道路分段和程序约束结合，Agent 有限修改后比较；无全局 TOPTW 求解，不保证全部预算。未知不是已通过。

**Agent 如何分工？** 模型负责需求/候选/理由，工具负责地点/交通/排程，受保护菜单负责修改；最多 2 轮修订、4 次模型、40 次工具、48 次外部请求、180 秒。用户最终采用。保留内部携程 MCP，未做对外 MCP 产品。

**多轮、画像、多日已做吗？** 当前行程多轮、少量澄清、可管理页面偏好、多日多交通已有；偏好不跨刷新，无云账户。初始分日顺序均分，车次住宿用户填写，不称已查到班次房间。

**携程接了什么？** query_ticket 提供地点、坐标、图片、详情；历史有真实调用，本次大修主要模拟验证。没有行程写入、购买或酒店餐馆全量集成，不把票务商品价当门票。

**为什么恢复还要核对？** 文件保存的是快照，不证明当前事实。分享复制清作者个人记录；本人恢复保留记录但未核实。重核全部地点取得新事实后可可信多轮，签名 12 小时或重启失效。

**隐私如何处理？** Key 只在标签页会话使用并经过本站服务端，不进分享/导出/库；对话、保存偏好、GPS、proof 也不进。同行、住宿、预订、已游览和自由文字仍可能公开，需审阅；没有加密备份或访问控制承诺。

**国内可用吗？** 国内高德、百度代理、本地前端库有帮助；默认海外 Valhalla 和托管可能受网络影响，道路可换自有服务，失败保留粗估/未知。本轮没有国内全链路实测。

**3D/照片真实吗？** 3D 是程序化空间示意，不是实景；图片有来源/参考标注，搜索不等于使用许可。未加载或不可读取照片不保证嵌进离线 HTML。

**效果提升多少、成本多低？** 无充分的真实用户基线和成本对照，不报虚构百分比。下一步评估匹配率、冲突率、规划耗时、修改次数、每次模型用量。

**是否上线？** 历史站点存在，W14 未发布。当前交付是可运行本地包、清单与哈希；真实服务、托管和真手机导航需部署后验收。
