# 线上澄清回答格式修复

2026-10-18，用户反馈原线上网址输入“我想去南京，3天时间”，回答“大概哪天出发，几个人一起去？”为“10月18日，两个人”后约3–5秒显示“本次规划结果不完整，请重试；当前行程未改变。”

## 原因与修改

该文案来自服务端 `MODEL_RESPONSE`。前端已保留原需求和澄清状态，未发现本次由流分块或丢失上下文导致。使用本地已有模型配置、同样原需求与回答作一次窄范围真实诊断，约1.1秒得到模型条件 `startDate:string`、`dayCount:number`、`companions:string`；严格归一化在 `companions` 失败，复现同一错误码。仅记录字段类型，未保存完整模型响应或凭据。

`companions` 实际表示儿童、老人等特殊同行需求，只接受枚举数组，不能保存“两个人”。原提示未明确字段类型、同行枚举或当前年份，直接整体归一化导致模型格式错误中止流程，连会被已验证表单覆盖的坏字段也会提前失败。

- 模型提示明确日期、时间、天数、交通及特殊同行条件的格式，区分人数与特殊同行需求；提供北京时间当前日期。未明示成人/儿童分类时不把人数自动分类，原中文回答仍完整传给后续规划。
- 先以已验证的表单和保留条件覆盖模型对应字段，再严格校验最终条件。HTTP 表单校验保持严格。
- 模型条件格式无效时，携原需求和最新回答最多调用一次模型纠正，不要求用户重新回答。仍受原请求模型/网络/时间预算限制；再次无效明确失败，不循环。
- 新增南京澄清、中文日期/人数格式、纠正次数及显式条件优先的回归用例，纳入 npm test 清单。两处历史离线 fixture 改为按 user 角色读取输入，适配此前地点散文引入的第二条 system 消息。
