## 2. 产品与实现原则

1. AI 根据完整需求提出候选地点、线路主题和访问顺序，真实数据匹配后再落图；模型生成的坐标、营业时间、票价和实时天气不能伪装成核实结果。
2. 采用同一份版本化行程数据驱动地图、时间轴、路线编辑、Agent、路书、收藏和分享。保存稳定站点 ID、分日结构、交通分段、来源和验证状态，避免每个功能形成一份互相漂移的行程。
3. 用户编辑先产生草稿，重新计算受影响的路段和排程，再提交新版本；异步旧请求不得覆盖新版本。失败时保留可恢复的上一版，允许撤销。
4. 校验区分“通过 / 冲突 / 未知”。不知道开放时间不能当成全天开放；交通估算不能标为导航路程；缺少数据时仍应提供可执行的修正入口。
5. Agent 使用有限次数的工具调用与修订，有取消、超时和费用/轮次上限。选点创意交给模型，地点身份、日期和时间约束由数据与程序检查；不追求无证据的“全局最优”。
6. 偏好以本次用户明确要求优先，历史偏好可查看、修改、清除；老人、儿童、轮椅等出行条件不能永久自动套用。密钥不进入路书、分享内容、画像、日志或导出。
7. 优先复用 Node 原生 HTTP、原生前端和现有地图，不为大修先迁移框架。新增模块以职责分离为目的，方便后续 Claude 修改表现层。
8. 新的外部服务尽量采用国内可访问来源及可配置适配器。需要新凭据时先完成可运行的适配与清晰的配置说明；真实联调未完成必须列为待办，不把模拟响应或估算当作真实验收通过。

## 4. 每个对话的执行与交接规则

1. 先读 `AGENTS.md`、本文件的当前任务与最近交接；只按需读老师文档和相关代码，不重新审计整个项目。
2. 接手后在本文件标记当前任务进行中，并写入自己的对话 ID（若工具可取得）；同一时刻只让一个主对话修改此项目。子代理仅用于当前小任务内可独立的短工作，不代替用户要求的新对话。
3. 完成当前小任务的代码、必要验证和状态记录。检查覆盖受影响行为即可；通过后停止，不例行重跑全套。对重要新逻辑写能发现真实错误的少量测试；纯文档不跑业务测试。
4. 在 `docs/Web大修交接.md` 写入已完成内容、修改文件、验证结论、真实服务/模拟区别、遗留问题、下一项具体任务。不要复制密钥、整段工具输出或完整对话。
5. 更新本计划的状态与 `AGENTS.md` 的事实，避免旧的“未实现”表与实际代码冲突。
6. 使用 `list_projects` 确认本项目，再通过 `create_thread` 在同一项目的 local 环境创建全新对话。用户已授权整条串行链，不需每次再问是否继续；不覆盖模型选项，沿用用户配置。下一个对话的 prompt 必须再次包含“每完成一项新建对话继续、减少检查、优先功能交互、保留携程 MCP 数据接入、Web 范围自主推进”，并给出交接路径和下一项验收。
7. 新建成功后用一次有界 `wait_threads` 确认开始或需要处理的情况，然后旧对话结束，提供新对话卡片。不要等待所有后续任务完成，不重复派发同一项；不要要求新对话频繁向旧对话汇报。
8. 若创建工具失败，保留交接并明确失败原因；不得把没有创建成功的对话称为已启动。确因外部凭据卡住时，完成独立部分，将该项标为部分完成且记录补验条件，再由新对话推进不依赖它的工作；最终交付保留未闭合项，不冒充全部完成。
9. W14 完成后停止创建工作对话并汇报交付；仍有实质未完成项时，为该项建立具体补完任务，不无限创建“继续优化”对话。
